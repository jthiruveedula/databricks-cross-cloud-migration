# Visual atlas

Five views of the same migration, each answering a question the others cannot. The worked example throughout is **Azure → GCP**, but the shapes hold for any cross-cloud pair — swap ADLS Gen2 for S3, Pub/Sub for Kinesis, and the lanes, gates, and states are unchanged. All six cloud-pair architecture diagrams are at the bottom of this page.

Each diagram is interactive: switch light/dark, play the guided views, trace a route between two nodes, or export the current state as PNG, SVG, or WebM. Every diagram also appears inline on the page that owns its subject, linked below.

<Callout client:visible variant="tip" title="Read them in this order">
  Architecture answers *what exists*. Data flow answers *what moves*. The runbook answers *in what order*. The sequence answers *what a single event experiences*. The lifecycle answers *what happens when one table fails its check*. Skipping to the runbook without the first two is how teams end up sequencing work they have not scoped.
</Callout>

## Editing these diagrams

The diagrams are generated, not hand-drawn. Each one is a typed JSON spec in `diagrams/`, rendered to a self-contained HTML file in `public/diagrams/` by [Archify](https://github.com/tt-a1i/archify):

```bash
npm run build:diagrams:check   # validate specs at showcase quality
npm run build:diagrams         # re-render every diagram
```

Edit the spec and re-render; never hand-edit the HTML. The rendered files are committed so that CI and the Pages deploy never depend on Archify being installed. Full contributor notes are in `CONTRIBUTING.md`.
