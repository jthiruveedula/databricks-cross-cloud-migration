# Model registry

Registered models carry more than the model artifact itself — version history, promotion state, and every downstream job or serving endpoint that references a specific model version. [MLflow](/ml/mlflow) covers experiment/run history; this page covers what happens once a run graduates to a registered, deployable model.

<Callout client:visible variant="warning" title="Stages do not exist in Unity Catalog — this is a redesign, not a translation">
  The Workspace Model Registry's four fixed stages (None/Staging/Production/Archived) are **not supported** for models in Unity Catalog. They are replaced by **aliases** — up to 10 custom, reassignable named pointers — plus tags for labelling, with the three-level namespace itself expressing environment.

  So `transition_model_version_stage()` has nothing to call in the target, and any promotion workflow, CI job, or dashboard keyed on `current_stage` needs rewriting rather than repointing. Decide the alias scheme during design: teams commonly map Production to a `champion` alias and Staging to `challenger`, but the naming is yours and the code that reads it has to change either way.
</Callout>

<Callout client:visible variant="prerequisite" title="Unity Catalog-based registry, not the legacy workspace registry">
  If source models live in the legacy workspace model registry, migrate to Unity Catalog's model registry in the target rather than reproducing the legacy pattern — it's the only registry model that gives you cross-workspace governance and lineage going forward, and you'd otherwise face this exact migration problem again next time.
</Callout>

## What to migrate per model

| Asset | Migration approach |
|---|---|
| Model versions | Re-register each version in target from its source artifact, preserving version order |
| Promotion state | **Translate stages to aliases** — the concept changes, and version numbers do not line up between source and target |
| Model signature | **Required in Unity Catalog.** A legacy model logged without one fails registration outright — see below |
| Input example | Carried if you re-log via `mlflow.pyfunc.log_model` with the original signature and example |
| Description and tags | Copy explicitly; these are metadata, not part of the artifact |
| Consumers (jobs, serving endpoints referencing a specific version/alias) | Update every reference to the target model name/version — see the reference audit below |
| Source-run lineage (`mlflow.source_run` / lineage tags) | Re-point to the *migrated* target run ID — see the lineage caveat below |

<Callout client:visible variant="warning" title="Re-registering a model orphans its lineage unless the source run was migrated too">
  A model version's lineage pointer (`source_run`/`run_id`) references the MLflow run that produced it. If you re-register the model in target without also migrating that run via [MLflow](/ml/mlflow), the pointer either breaks or silently references a run ID that doesn't exist in the target tracking server — "which experiment produced this model" becomes unanswerable. Migrate the source run first, then re-register the model version against the *migrated* run's new ID, not the original source run ID.
</Callout>

## Two different problems — pick the right one first

`copy_model_version()` is the tool Databricks recommends for moving model versions into Unity Catalog, and it is genuinely good: it takes a source `models:/name/version` URI and a three-level destination, and creates the destination model if it does not exist. It needs MLflow client 3.4.0 or above.

<Callout client:visible variant="warning" title="It does not bridge two accounts, which is the case a cross-cloud migration is actually in">
  `copy_model_version()` copies **within one registry** the client is connected to — the Workspace Model Registry to Unity Catalog inside the same account, or between workspaces sharing a metastore. A cross-cloud move has two accounts, two metastores, and no shared registry, so there is no single call that spans them.

  For cross-cloud the pattern is unavoidably **download the artifacts from source, then re-log and register in target**, which is what the script below does. When [metastore migration](/governance/metastore-migration) says model versions are "artifacts, not metadata", this is what it means.
</Callout>

### Cross-cloud: download, re-log, re-alias

<CodeBlock client:visible language="python" filename="migrate_model_versions.py" code={`import mlflow
from mlflow import MlflowClient

source_client = MlflowClient(tracking_uri=SOURCE_TRACKING_URI, registry_uri=SOURCE_REGISTRY_URI)
target_client = MlflowClient(tracking_uri=TARGET_TRACKING_URI, registry_uri=TARGET_REGISTRY_URI)

SOURCE_NAME = "churn_model"                       # 2-level, legacy workspace registry
TARGET_NAME = "prod_gcp.ml.churn_model"           # 3-level, required by Unity Catalog

mlflow.set_registry_uri(TARGET_REGISTRY_URI)
target_client.create_registered_model(TARGET_NAME)

# Oldest first, so target version numbers ascend in the same order as source.
# They will NOT be the same numbers -- record the mapping.
versions = sorted(
    source_client.search_model_versions(f"name='{SOURCE_NAME}'"),
    key=lambda v: int(v.version),
)

version_map = {}
for mv in versions:
    local_path = source_client.download_artifacts(mv.run_id, "model")
    result = mlflow.register_model(f"file://{local_path}", TARGET_NAME)
    version_map[mv.version] = result.version

    for key, value in (mv.tags or {}).items():
        target_client.set_model_version_tag(TARGET_NAME, result.version, key, value)
    if mv.description:
        target_client.update_model_version(TARGET_NAME, result.version, description=mv.description)

    # Stages do not exist in Unity Catalog. Translate to an alias.
    if mv.current_stage == "Production":
        target_client.set_registered_model_alias(TARGET_NAME, "champion", result.version)
    elif mv.current_stage == "Staging":
        target_client.set_registered_model_alias(TARGET_NAME, "challenger", result.version)

print(version_map)  # source version -> target version, needed by every consumer
`} />

<Callout client:visible variant="warning" title="A model without a signature will not register in Unity Catalog">
  Unity Catalog requires a model signature. Any model logged years ago without one fails registration, and on a legacy estate that is not a rare case — it is a batch of models that all fail at once, late, when someone finally runs the migration script.

  Find them during discovery rather than at cutover: check `mv.signature` on every source version and list the gaps. The proper fix is to re-log the model with a signature inferred from a sample input. The escape hatch, if you must move an unmodifiable artifact, is `MLFLOW_SKIP_SIGNATURE_CHECK_FOR_UC_REGISTRY_MIGRATION=true` — but it works **only with `copy_model_version()`** on MLflow 3.4.0+, which as noted above is not available across accounts. So for a cross-cloud move, re-logging with a signature is usually the only path, and that is a per-model piece of work to schedule.
</Callout>

<Callout client:visible variant="tip" title="Version numbers will not match, and everything downstream references them">
  Target versions are assigned in registration order and start at 1. A model at source version 47 will not be version 47 in the target. Keep the `version_map` the script prints: it is what every job, serving endpoint, and notebook pinned to `models:/name/47` needs in order to be repointed. Pinning consumers to an **alias** instead of a version number is the fix that stops this recurring.
</Callout>

## Auditing consumers before cutover

<Callout client:visible variant="warning" title="A model reference is a dependency, same as a table reference">
  Every job, pipeline, or serving endpoint that loads `models:/churn_model/Production` breaks twice over in the target: the name is two-level, and `Production` is a stage that no longer exists. It has to become `models:/prod_gcp.ml.churn_model@champion`. Treat this exactly like the table dependency mapping in [dependency mapping](/discovery/dependency-mapping) — trace every consumer before cutover, don't discover them from broken jobs afterward.
</Callout>

<CodeBlock client:visible language="bash" filename="find_model_references.sh" code={`SRC=./exported-notebooks ./exported-jobs

# Every model reference, so nothing is missed
grep -rn "models:/" $SRC

# The two that MUST change, separated out because they fail differently:
# 1. Stage-based URIs -- the stage does not exist in Unity Catalog
grep -rnE "models:/[^\\"']+/(Production|Staging|Archived|None)\\b" $SRC

# 2. Two-level names -- Unity Catalog requires catalog.schema.model
grep -rnE "models:/[A-Za-z0-9_-]+(/|@)" $SRC | grep -vE "models:/[^/]+\\.[^/]+\\.[^/@]+"

# And the API call that has nothing to call in the target
grep -rn "transition_model_version_stage" $SRC
`} />

## Validation

- Load each migrated model version in target and run it against a fixed test input; compare predictions to the source model's output for the same input.
- Confirm **alias** assignments in target point at the intended version — not just that "a version exists". There are no stages to check.
- Confirm every source version had a signature, or was re-logged with one; a silent gap here means a model that never registered.
- Verify every consumer found in the reference audit above resolves correctly against the target registry before cutover.

## Rollback

Keep the source model registry and its serving endpoints live through hypercare. If a target model version is wrong, fix the registration or re-run the migration script for that version — this is a registry-metadata fix, not an environment rollback.

## Automation opportunity

- Script the consumer reference audit as a repeatable check (grep across the [asset inventory](/discovery/asset-inventory) notebook/job export), not a one-time manual search.
- Automate alias re-application from the source-to-target version map the migration script emits, so it is not re-typed per model.
- Scan every source model version for a missing signature during discovery and report the list — this is the failure that arrives late and in bulk.
